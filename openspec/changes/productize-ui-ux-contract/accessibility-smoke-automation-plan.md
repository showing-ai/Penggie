# Accessibility Smoke Automation Plan

Task 7.6 decides which accessibility checks are stable enough to automate now
and which must stay in manual QA until Penggie has reliable runtime AX harnesses.

## Decision

Automate source-level accessibility guardrails only.

Do not automate live VoiceOver navigation, Dynamic Type rendering, reduced
motion behavior, or macOS focus traversal yet. Those checks depend on a live
Codex/Ghostty session, window focus, system accessibility settings, and terminal
frame timing; making them CI gates now would create noisy failures and could
encourage local state shortcuts.

## Automated Now

The stable smoke check is `scripts/qa/check-accessibility-smoke-source.sh`.
It verifies that the currently implemented product surfaces keep the required
accessibility hooks and evidence documents:

- Setup controls expose labels, values, hints, and combined status text.
- The create action exposes a label and state-specific hint.
- Raw Terminal and Reading mode switching hide the inactive surface from
  accessibility traversal.
- Terminal-owned candidate rows expose label, value, hint, and selected trait.
- Candidate row values are generated by the shared
  `PenggieTerminalSurfaceCandidateAccessibility` helper, not local per-surface
  strings.
- Tool/detail disclosure exposes expanded/collapsed state.
- The send affordance exposes an accessibility label.
- Manual QA and release review documents still contain VoiceOver, keyboard-only,
  syncing, unsafe confirmation, and terminal-truth evidence requirements.

This script is intentionally source/document based. It can run repeatedly
without launching a second Codex CLI, a second Raw Terminal session, or a live
VoiceOver automation session.

## Manual For Now

Keep these checks manual and record evidence in the release review template:

- VoiceOver rotor traversal through setup, Reading, composer, overlays, Raw
  Terminal, recovery, and confirmations.
- VoiceOver activation of terminal-owned rows and destructive confirmations.
- Dynamic announcements for checking, launching, working, approval required,
  permission required, projection degraded, selection syncing, exited, missing
  Codex, and launch failed.
- Dynamic Type or larger text layout behavior.
- Reduced motion behavior for disclosure, focus affordances, surface switching,
  and overlay transitions.
- Keyboard-only end-to-end journeys through real Codex/Ghostty terminal state.

These remain manual because the accepted product contract requires terminal
ground truth from the same Ghostty/Codex session. A brittle automation harness
that drives a separate process or asserts stale local UI state would violate the
contract.

## Revisit Criteria

Promote a manual check into automated smoke coverage only when all of these are
true:

- It can run without creating a second user-visible Codex session.
- It does not require a local command/model/resume/approval/permission list.
- It does not assert a local selected index.
- It can wait for terminal-frame evidence instead of sleeping on wall-clock
  timing.
- It has deterministic pass/fail output on developer machines and CI.
- It still leaves Raw Terminal as the audit/control surface for low-confidence
  terminal state.

## Validation

Run:

```bash
scripts/qa/check-accessibility-smoke-source.sh
scripts/qa/check-product-grade-ui-ux-manual-qa.sh
openspec validate productize-ui-ux-contract --strict
openspec validate --all --strict
```
